# v0.1.0

Release date: 2026-04-11

Release name: Initial modernized cut

## Summary

This is the first clean release of `model-behaviour-toolkit` as its own modern repo.

The main achievement of this release is structural:

- useful legacy prompt ideas were extracted
- lore-heavy framing was cut back
- the repo was reorganized into beginner-friendly and maintainer-friendly layers
- copy-ready starting points were added so the toolkit is usable without reading everything

## Highlights

### 1. The repo now has a clear usage ladder

Users can enter through:

- [docs/user-manual.md](../user-manual.md) if they are new
- [examples/README.md](../../examples/README.md) if they want copy-ready prompts
- [bundles/README.md](../../bundles/README.md) if they want reusable defaults
- [presets/README.md](../../presets/README.md) if they want work-specific overlays

### 2. The core prompt modules were extracted and modernized

The first module set covers:

- baseline setup
- boundary-aware collaboration
- session restoration
- portable recovery
- handoffs
- execution contracts
- output review
- creative reframing

### 3. The repo now supports both users and maintainers

Beginner path:

- [docs/user-manual.md](../user-manual.md)

Maintainer path:

- [CONTRIBUTING.md](../../CONTRIBUTING.md)
- [docs/how-to-add-a-module.md](../how-to-add-a-module.md)
- [docs/release-checklist.md](../release-checklist.md)

## Included In This Release

- Root documentation and onboarding
- Legacy inventory and migration guidance
- Core modules in `modules/`
- Ready-to-paste bundles in `bundles/`
- Work-specific presets in `presets/`
- Copy-ready workflows in `examples/`
- Contributor and release documentation

## What This Release Does Not Try To Do

- preserve the full identity or terminology of the legacy repos
- package historical logs as active toolkit content
- present the new repo as a direct one-to-one port of the archive
- solve every prompt use case on day one

## Upgrade Framing

Compared with the legacy source material, this release deliberately favors:

- plain language over mythology
- explicit state over fake continuity
- practical modules over giant ritual prompts
- readable onboarding over insider context

## Next Likely Directions

- refine examples based on real usage
- add more role-specific presets only where they earn their keep
- continue separating archival source material from the modern toolkit
